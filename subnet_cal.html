Walkthrough

Calculator

An IPv4 address is 32 bits, written as four decimal numbers 0–255 (one per byte, called an octet) separated by dots. Example: 192.168.10.130.
The number after the slash is the prefix length — how many bits, counting from the left, are reserved for the network portion of the address. /26 means the first 26 of the 32 bits identify the network; the remaining 6 bits identify hosts within it. CIDR stands for Classless Inter-Domain Routing, the notation that replaced the old class A/B/C system.
Network bits Host bits what do the 1s and 0s mean?
These bits are fixed for every device on the subnet — they never change between hosts. Together they form the network's identity, the same on every address inside it.
These bits are free to vary and identify individual devices within the subnet. With n host bits you get 2ⁿ possible combinations — two of which (all-0 and all-1) are reserved, leaving the rest as usable host addresses.
Each octet (like 192) is really 8 binary digits. 192 in binary is 11000000 — that's 128+64, since each position represents a power of two (128, 64, 32, 16, 8, 4, 2, 1 from left to right) and a bit is 1 if that value is included in the total. A 1 means "this power of two is switched on"; a 0 means it's switched off. Whether a given bit belongs to the network or host portion depends only on its position relative to the prefix length, not on its value.
Includes wildcard mask
A wildcard mask is a subnet mask with every bit flipped (255 minus each octet of the mask). Routers use it instead of a subnet mask in OSPF network statements and standard/extended ACLs — a 0 bit still means "must match exactly," but a 1 bit now means "don't care," the opposite of how a subnet mask reads. For /26 (mask 255.255.255.192), the wildcard is 0.0.0.63.

Magic number method

A shortcut that skips binary entirely. Find the "interesting octet" — the one where the subnet mask isn't 0 or 255. Magic number = 256 minus that mask value; it's the size of each block. List multiples of the magic number in that octet and find which two the address falls between: the lower one is the network address, one below the next multiple is the broadcast address. Same result as the binary method, just faster once memorized.

VLSM — variable-length subnetting

VLSM carves one address block into multiple subnets of different sizes, so each department or link gets only as many addresses as it needs instead of one fixed size for everyone. The standard approach: sort requirements largest-first, size each subnet to the smallest block that fits, and allocate them back-to-back starting from the base network so nothing overlaps.
The one big block of addresses you're starting with, before splitting it up — for example, the address range your ISP or head office gave you.
How big that starting block is, in the same /CIDR notation used above. A /24 is 256 addresses total; VLSM will carve subnets for each row out of that block, largest requirement first.

Capacity is the number of usable host addresses in that subnet (block size minus the network and broadcast addresses) — it's always the same as or larger than what you asked for, since subnets only come in powers of two.

IPv6 prefix breakdown

IPv6 addresses are 128 bits, written as eight groups of 4 hex digits separated by colons, with a run of zero groups optionally compressed to "::". The prefix length still marks the network/interface-ID boundary, same idea as CIDR, but subnets are normally sized in fixed /64 blocks rather than counted by host demand — there's no host-exhaustion math to do.
Eight groups of up to 4 hex digits (0–9, a–f), separated by colons. A run of one or more all-zero groups can be shortened to "::" once in the address — here it stands in for two zero groups.
Works exactly like the IPv4 prefix above: it marks how many bits, from the left, are the network / routing portion. Most end-user subnets use /64 by convention, regardless of how many devices are actually on them.
Network / routing prefix Interface ID
IPv6's name for what IPv4 calls the "host portion" — the part of the address that identifies one specific device, not the network it's on.
Address types EUI-64 / SLAAC
The first few hex digits tell you what an IPv6 address is for:
• fe80::/10 (starts with fe80) — link-local. Auto-assigned on every interface, never leaves that local network segment, never routed.
• fc00::/7, in practice fd00::/8 (starts with fd) — unique local (ULA). IPv6's equivalent of IPv4's private ranges (like 192.168.x.x) — not globally routable.
• ff00::/8 (starts with ff) — multicast. Delivered to a group of interfaces at once; IPv6 has no broadcast address, multicast replaces that role.
• 2000::/3 (starts with 2 or 3) — global unicast. Publicly routable on the internet, the IPv6 equivalent of a public IPv4 address.
EUI-64 is how a device can build its own interface ID from its MAC address, without needing DHCP — part of SLAAC (Stateless Address Autoconfiguration). Take the 6-byte MAC address, split it in half, insert fffe in the middle to make 8 bytes, then flip the 7th bit of the very first byte (the "universal/local" bit, worth 0x02). Example: MAC 00:0c:29:12:34:56 → flip 0x00 to 0x02 → interface ID 020c:29ff:fe12:3456.
